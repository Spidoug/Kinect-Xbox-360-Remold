# Quick start — V1

## 1. Build SynKinect Studio and the native runtime

Windows:

```text
BUILD.cmd
```

The root launcher first bootstraps the pinned Processing/JOGL/GlueGen dependencies, rebuilds the self-contained SynKinect Studio, and then builds the native Windows runtime. The body tracker and surveillance video writer are part of the Studio source and require no model/runtime/FFmpeg download. It keeps the console open on success or failure and shows the log location.

Then run the generated:

```text
drivers\windows\binaries\KINECT.cmd
```

Linux first build:

```bash
bash scripts/linux/BUILD-STUDIO.sh
bash drivers/linux/INSTALL.sh
```

The Studio build creates the JAR, stages the pinned graphics dependencies, and generates `applications/binaries/linux-x64/java` with `jdeps`/`jlink`. If no suitable JDK 17+ exists on the build machine, it downloads and verifies Microsoft OpenJDK 17 automatically. The normal-user Linux control panel asks for sudo/pkexec only when installation actually starts; that installer resolves the native driver build dependencies before compiling the driver runtime.

or build a fresh Debian package:

```bash
bash drivers/linux/packages/build-deb.sh amd64
```

## 2. Start SynKinect Studio

These launchers are generated by the build and are not committed to the repository.

Windows:

```text
applications\binaries\windows-x64\SynKinectStudio.cmd
```

Linux:

```bash
bash applications/binaries/linux-x64/SynKinectStudio.sh
```

SynKinect Studio is intentionally a **standard-user application on both Windows and Linux**. Do not run it as Administrator/root. The Home system controls launch the platform control panel without elevation; UAC/sudo/pkexec is requested only for operations that modify system state such as driver install/removal or protected service configuration.

Tabs:

- `1` — 3D Scanner
- `2` — Acoustic Scanner
- `3` — Microphones
- `4` — Surveillance
- `5` — Interactivity

## 3. First HQ 3D scan

1. Select the physical Kinect in the Studio shell.
2. Run **CALIBRATE** for that Kinect using a large flat surface at the requested distances.
3. Position the object in the close/mid depth range.
4. Start the scan and move slowly with substantial overlap between views.
5. Complete a full sweep when practical so loop closure can correct drift.
6. Pause/finish capture.
7. Run the HQ build. The final reconstruction uses retained keyframes, pose refinement, 2× multi-frame Depth SR and the 288³ TSDF rather than exporting the live preview.
8. Export OBJ, STL or PLY.


### Acoustic Scanner

The Acoustic Scanner consumes the Kinect four-channel array continuously while its tab is active. `AUTO` follows a confident DOA/TDOA estimate; `MANUAL` lets you click the radar to choose the steering angle. The green beam line is the current beamformer direction and the processed mono signal is sent to the system playback output. Keys `A` and `M` switch modes.

### Surveillance day/night

Surveillance uses RGB only in normal light. After the configured low-luminance hysteresis it reconnects the same physical video endpoint as IR only. It never subscribes Depth. A return-to-RGB check is only attempted after sustained IR evidence of increased ambient light and the configured cooldown. Leaving the Surveillance tab releases IR so Scanner/Interactivity can reacquire RGB.

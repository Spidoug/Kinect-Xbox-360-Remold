# Repository layout and ownership — V1

V1 uses a clean platform/lifecycle layout. There is one application source tree and separate Windows/Linux native runtime trees.

```text
.
├── applications/
│   ├── processing/SynKinectStudio/
│   └── binaries/{windows-x64,linux-x64}/
├── drivers/
│   ├── windows/{source,binaries}/
│   └── linux/{source,binaries,packages}/
├── docs/
│   ├── images/
│   ├── linux/
│   └── windows/
├── licenses/
└── scripts/{linux,windows}/
```

## Ownership rules

- `applications/processing/SynKinectStudio/` — editable Processing source and app configuration.
- `applications/binaries/` — exported application runtime payloads only.
- `drivers/windows/source/` — editable Windows native code/build/install source.
- `drivers/windows/binaries/` — final Windows native publish target generated by the V1 build.
- `drivers/linux/source/` — editable Linux native code and service/integration definitions.
- `drivers/linux/binaries/` — staged compiled Linux runtime.
- `drivers/linux/packages/` — DEB/RPM packaging.
- `docs/` — cross-platform and platform-specific behavior/operation documents.
- `docs/images/` — documentation-only screenshots and visual reference assets; use descriptive lowercase `kebab-case` filenames.
- `scripts/` — repository-level helpers.
- `licenses/` — retained third-party license texts.

Generated native binaries must not be placed inside source trees. Application `.pde` files must not be placed beside exported executables.

## Windows binary target

`drivers/windows/binaries/` is intentionally a publish target. In the GitHub source package it contains documentation/placeholders; `drivers/windows/BUILD.cmd` recreates it with the complete current binary package. Required output is documented in `drivers/windows/BINARY-PAYLOAD.md`.

## Application source rule

V1 has one Processing source file:

```text
applications/processing/SynKinectStudio/SynKinectStudio.pde
```

All five user-facing modules are internal tabs of SynKinect Studio. New application behavior should be added to this unified source rather than creating additional top-level sketches.

## Documentation media rule

Documentation screenshots and presentation images belong in `docs/images/`. Runtime icons do not: the application source-of-truth icon remains `applications/processing/SynKinectStudio/data/synkinect-studio-icon.png`, Processing export icon sizes remain beside the sketch, and generated runtime copies remain under `applications/binaries/`. See the [documentation-image manifest](images/README.md) for the asset list and naming policy.
